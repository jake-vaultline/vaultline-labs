# Drive Report — design + data contract

**Status: DESIGNED 2026-08-07.** Template at `report-template.html` (sample data).
Not yet generated by the app.

---

## Why this was designed before the code that fills it

The app runs once per drive. **The report gets emailed to a producer, pasted into
Slack, and opened in a meeting** — it travels into rooms the app never reaches. It is
the distribution mechanism, not a checkbox feature (spec §7).

Designing it first also fixes the data contract: §3 below is now the definition of done
for Pass 2, rather than something discovered halfway through writing AVFoundation code.

---

## 1. Output formats

| Format | Purpose | Notes |
|---|---|---|
| **HTML** — single self-contained file | The one that gets pasted into Slack and opened by six people. Highest leverage | Inline CSS/JS, no external requests. Must open offline |
| **PDF** | Emailed, printed, attached to a handover | Print stylesheet already in the template: light surface, `page-break-inside: avoid` per section, data tables hidden |
| **CSV** | For the person who wants to pivot it themselves | Flat per-file rows plus a summary block. **Built 2026-08-27 (VLP-491).** Also the complete export: nothing in it is capped by the report's display limits, and every "not shown in the report" note points here |

The HTML template is the master. PDF is that template printed; CSV is a separate flat
export.

## 2. Structure, and why each block is the form it is

| Block | Form | Why |
|---|---|---|
| Masthead | Real logo lockup + rule | Actual wordmark from `branding/`, white-on-charcoal, with the thin rule running out from it |
| Hero row | 4 stat tiles | Single headline figures. Not a chart — nothing is being compared |
| Capacity | One stacked bar | Part-of-whole, two parts |
| What's on it | Horizontal bars | Magnitude comparison, ranked |
| Codecs / Resolutions | Horizontal bars, side by side | Same form, two dimensions. **Two charts, never a dual axis** |
| Cameras detected | Labelled chips | Identity + count. A chart would add nothing |
| Media by year | Column chart | Change over time |
| Top formats | Horizontal bars | Same form as "What's on it", one level finer. Added to the report 2026-08-27; the app window had always shown it |
| Largest folders / files | Tables with inline mini-bars | Ranked identity where the label matters more than the shape |
| Worth a look | Status list, icon + label | Status, never color alone |

**The "Worth a look" block is the one that converts.** A hobbyist skims it. A post
supervisor seeing *"1,904 files have no verified second copy — 402 GB"* books a call.
It is deliberately last, deliberately specific, and deliberately not a sales pitch.

## 4. Brand + palette notes

Colors follow the `vaultline-brand` "Archive Console" palette. Two deviations, both
deliberate and both documented in the template's CSS header:

1. **Chart marks use a darker amber than brand `#D7A84F`.** The brand amber sits above
   the OKLCH lightness band for chart marks and fails validation as a data color. Marks
   use `#A8761F` on the light report surface. **Brand amber remains canonical** for UI
   accents, rules, and dark-surface use — this is a derived chart step from the same
   hue, not a palette change.
2. **The report body is light (`Soft White #F4F1EA`), not dark.** Brand direction leans
   dark, and the masthead and footer honor that — but a dark PDF is unusable printed and
   this document exists to be shared and printed. Light body, dark bookends.

Palette validated with the dataviz validator against both surfaces:

```
light surface #F4F1EA → #2F6FE0 / #A8761F   all six checks PASS
dark  surface #0B0F14 → #4C8DFF / #B07F2E   all six checks PASS
```

**Color never carries identity anywhere in this report.** Every bar is direct-labeled,
every status item ships an icon plus text. That is what keeps it readable in
colorblind, greyscale, and printed conditions — which for a document that gets printed
and forwarded is not a nicety.

Typography is a neutral system stack pending a brand type decision — the brand skill
locks color and logo direction but the summary doesn't specify a typeface.

### Logo assets

Real marks from `vaultline-labs/branding/source-copies/`, not a text approximation:

| Asset | Where | Treatment |
|---|---|---|
| `vaultline-white-transparent` | Masthead | Cropped to its alpha bounding box, resized to 132px tall, embedded as a base64 data URL at 42px display (≈3× for retina) |
| `vaultline-icon-white-transparent` | Footer, beside the tagline | Same, 96px source at 23px display |

Both are inlined so the HTML stays a single self-contained file that opens offline —
a report that renders a broken image icon when forwarded is worse than one with no logo.

The source PNGs are square with heavy transparent padding, so **crop to the alpha bbox
before use** or the mark floats in dead space. Cropped ratios: wordmark 4.00:1,
icon 1.39:1.

**Only the white versions are used**, because both the masthead and footer are
Charcoal. The black versions are for light surfaces — nothing in this report needs them
today.

**Still needed:** vector (SVG/PDF) versions. These are 1254px PNGs, which is fine for
screen and adequate for print at this size, but a logo should not be a raster. Ask for
the vector source before this goes anywhere large-format — a Sandbox walkthrough, a
printed one-pager, or the NFC drive labels from Experiment 001.

Voice in the footer follows the brand voice rules: concrete and plain-spoken
("You already captured this footage. The hard part is finding it again three years
later."), tagline is the locked ICP-clarity pick.

## 5. Open questions

- **"No verified second copy" is the strongest line in the report and the app cannot
  currently compute it.** A single drive scan has no knowledge of other drives. Options:
  (a) drop it from the free app and make it a Vaultline-only capability — which is
  honest and makes the bridge concrete; (b) let the user scan two drives and compare;
  (c) reframe as "files that exist only once *on this drive*," which is weaker but
  computable. **Leaning (a)** — it's the single best argument for the paid product, and
  claiming it without evidence would be exactly the kind of wrong number that discredits
  a report
- Whether the report asks for an email before export (leaning **no** — friction against
  a distribution asset)
- Whether to include the scanned folder path in shared reports, or redact by default —
  paths leak client names
- Proxy bitrate assumptions to publish
- ~~Whether the CSV is per-file rows, summary blocks, or both~~ — **decided 2026-08-27 (VLP-491): both.**
  The export menu had promised "every file" since 0.1 and shipped aggregates plus the
  largest 100. It now carries a full `All files` inventory sourced from `MediaIndex.all`,
  capped at `Walker.maxMediaRefs` rows and saying so in-table when the cap is hit. Byte
  columns ship beside a human-readable size and a share; numeric fields are unquoted so
  spreadsheets type them as numbers

## 6. Display limits, and the parity rule

**The app window and the report show the same sections, in the same order, at the
same depth.** They did not for the first two versions: the report cut duplicates at
ten groups while the window showed twenty-five and told the reader to open the report
for the rest, the window showed five cameras against the report's ten, and frame
rates, media-by-year and three of the four "Worth a look" items existed only in the
report.

Every limit now lives in `Show` (`app/Sources/Models.swift`) and both surfaces read
from it. Anything a surface leaves out says so, with the count, and points at the CSV.

The CSV is never limited by `Show`. It is the complete export.
